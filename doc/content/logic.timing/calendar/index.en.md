## Description

This module reads a calendar in iCal / ics format and provides information about the next appointment. This can be used to control alarms or visualize appointments.


Recurring events (series) are currently **not** fully supported; while series definitions are not fully included yet, exceptions to recurring events are considered.

## Properties

### Inputs


| Name | Port type | Description |
| --- | --- | --- |
| iCal Calendar | Time | Input where an iCal / ics calendar is provided. Since parsing large calendars may create notable load on X1, refresh intervals should be generous and peak times (e.g., full hours) should be avoided. Good results were achieved with e.g. 2h 22min refresh interval. |



### Parameters


| Name | Port type | Description |
| --- | --- | --- |
| Including Parameters | Integer | To filter appointments of a day, appointments can be filtered by including parameters. An appointment is shown only if **all** 0..10 including parameters match. Filtering uses "String.StartsWith(.. OrdinalIgnoreCase)", so custom prefixes are also supported. |
| Including Parameter x | Integer | One including parameter. Example: in an iCal generated by Microsoft Exchange, to include only booked appointments, use parameter "X-MICROSOFT-CDO-BUSYSTATUS:BUSY". |
| Excluding Parameters | Integer | To filter appointments of a day, appointments can be filtered by excluding parameters. An appointment is shown only if **none** of 0..10 excluding parameters match. Filtering uses "String.StartsWith(.. OrdinalIgnoreCase)", so custom prefixes are also supported. |
| Excluding Parameter x | Integer | One excluding parameter. Example: to hide all entries named "Focus Time", use parameter "SUMMARY:Focus Time". |
| Send next event | Timespan | Defines the time after start of the current appointment (0 sec .. 15 min) when the next appointment is announced at outputs. |
| Event summary format | Text | Supports formatting the output text with placeholder "\{x\}" for the next appointment. Available values: *0* [DateTime] start time, *1* [TimeSpan] duration, *2* [String] subject/title, *3* [String] location. If no format is defined, output "Next event summary" remains empty. Formatting options: [Date and time formats](https://learn.microsoft.com/en-us/dotnet/standard/base-types/standard-date-and-time-format-strings) and [TimeSpan formats](https://learn.microsoft.com/en-us/dotnet/standard/base-types/standard-timespan-format-strings). |
| Unknown Event Text | Text | Text sent to "Next event summary" output if no event is scheduled for the next six months. |



### Outputs


| Name | Port type | Description |
| --- | --- | --- |
| Next event | Time | Returns start time of the next appointment. The next appointment is shown after "Send next event" elapsed after start of current appointment. If no appointment is found for the next seven days, default timestamp "01.01.0001 00:00:00" is returned. Parameter "Next event summary" is always updated immediately **before** this output. |
| Next event summary | Time | Returns a summary of the next appointment based on "Event summary format". If no appointment exists for the next seven days, a configured text ("Unknown Event Text") can be output. Parameter "Next event" is always updated immediately **after** this output. |

## Usage

### Example: Determine wake-up time


If your routine starts at different times that cannot be mapped well to weekdays (-> schedule), it makes sense to evaluate existing calendars. Often multiple calendars exist in parallel, so the next or earliest appointment must be selected from all of them.


This module takes the next appointment times from 1..10 calendars and determines the next/earliest one, which can then be forwarded to the alarm clock module.


Because the alarm clock must be activated to actually wake up, next appointments can still be sent throughout the day. The alarm will only trigger if activated during daytime.


![Alarm clock (wake-up time) - Read calendar and holiday calendar](/content/logic.timing/img/calendar--example01.png)
*First, appointments are read from an Exchange Online calendar and holidays are provided by a web service. To use data across multiple logic sheets, values are stored in X1 variable data points.*


![Alarm clock (wake-up time) - Use calendar and holiday calendar](/content/logic.timing/img/wakeup--example02.png)
*In this example, wake-up time is determined from a calendar. Holiday calendar and workday configuration support selecting default wake-up time.*


Default wake-up times can be provided via scenes, schedules (e.g., weekday/weekend), or input devices to one of the inputs.


For an alarm to trigger, the appointment must be sent in time. For example, if alarm sequence duration is 30 min and lead time of wake-up-time module is 45 min, the appointment must be sent at least 1h 15min before actual wake-up time by the Calendar module.


If a [Holiday calendar](/en/logic.timing/holiday) is used and a holiday is detected for today, the next holiday is only sent shortly after midnight and may therefore update default wake-up time.
